The loop

Profile→ Generate code→ Guardrail gate→ Sandbox execute→ Repair on error→ Verify answer→ Grounded report

Guardrails

  • Bounded execution: timeout, output cap, scoped run dir; no network, no process spawning, no writes outside the run dir.
  • Reports are grounded in the code's actual printed output — no invented numbers.
  • If the repair / verify budget is exhausted, the result is labelled UNVERIFIED.
  • Every analysis is appended to the audit trail.

Working with your data

  • Ingest a CSV, Excel, or Parquet file (via chat or ingest) to bring it into the module.
  • Ask the copilot to show an editable table to review or fix the source data before analysing.
  • Analyze the ingested dataset here or from chat.
